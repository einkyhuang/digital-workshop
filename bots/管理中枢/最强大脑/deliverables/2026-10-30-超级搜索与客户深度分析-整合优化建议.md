## 2. 重叠与缺口

### 2.1 重叠

1. **超级搜索多份拷贝**：GitHub public ↔ `Desktop/skills/全能搜索skills/...` ↔ `全能搜索skills 2` ↔ `gtls.tgz` ↔ Grok Bot `workflows/global-trade-lead-search`。  
2. **通用话术 JSON 双仓重复**：`global-foreign-trade-skills-hub` 与 `zhanfa-trade-skills-hub` 当前三份 JSON **内容同构**，垂类仓未真正垂类化。  
3. **行业销售包与通用中台**：`foreign-trade-hub` / `lighting-trade-hub` 内嵌的 `customer_tier_rules`、`sales_scripts`、`email_templates` 与通用仓同源或改编；易出现「改了一处、另一处未同步」。  
4. **客户库查询 vs 公网发现**：`lightleads` / 汽配 Skill 查的是**已有私有名录**；`global-trade-lead-search` 做的是**公网可审计发现**。能力相邻但证据链不同，产品上应拆开命名，避免都叫「超级搜索」。

### 2.2 缺口

1. **DCA 无 GitHub 单一事实源** → 无法 CI、无法给外部/其他 bot 稳定 `git pull`。  
2. **行业包未统一进「超级外贸技能库/02」**：照明、汽配仍散落在 zip / 桌面业务文件夹 / 工作台 bot 目录。  
3. **云端持续迭代未闭环**：SOP 描述了 ingest→GitHub→Cloudflare→企微；本地 `01_待训练`/`已训练` 几乎空，`trade_hub.db` 为空，ingest 脚本路径指向另一工程目录（`布料训练数据/...`）。  
4. **Grok Bot 技能库同步机制未文档化**：Box `workflows/` 与 Desktop/GitHub 谁先谁后、如何发布新版本，缺少发布清单。  
5. **汽配 Skill 绑定本地 JSON 路径**，不可直接云端调用；照明经 Vercel API 相对更接近「可调用」。  
6. **合规边界**：GTLS/DCA 均禁止编造联系方式、禁止擅自外发；私有客户库绝不能进 public 仓——这一点现有 GTLS README 已强调，整合时必须保持。

## 3. 推荐分层架构

目标：**通用技能（Core）可跨行业复用；行业包（Pack）只挂规格、认证、私有名录适配与话术变体；私有客户数据永远不进 Skill 源码仓。**

```
                    ┌──────────────────────────────────────┐
                    │  调用面：Grok Bot / Codex / agy / IDE │
                    │  Skill 名或 CLI / 可选 MCP            │
                    └──────────────────┬───────────────────┘
                                       │
         ┌─────────────────────────────┼─────────────────────────────┐
         ▼                             ▼                             ▼
 ┌───────────────┐            ┌────────────────┐            ┌────────────────┐
 │ Core A        │            │ Core B         │            │ Core C         │
 │ 超级搜索      │            │ 客户深度分析   │            │ 通用外贸中台   │
 │ GTLS          │──线索───▶  │ DCA            │──开发建议─▶│ 话术/星级/邮件 │
 │ public repo   │            │ 待建 public/   │            │ private hub    │
 │               │            │ private repo   │            │                │
 └───────┬───────┘            └───────┬────────┘            └───────┬────────┘
         │                            │                             │
         └────────────┬───────────────┴──────────────┬──────────────┘
                      ▼                              ▼
         ┌────────────────────────┐     ┌────────────────────────────┐
         │ Industry Packs         │     │ Private Data Services      │
         │ lighting-trade-hub     │     │ lightleads-api (照明名录)  │
         │ foreign-trade-hub      │     │ 汽配/服装私有库 API（待建）│
         │ auto-parts-trade-hub   │     │ 桌面「客户搜索」批次归档   │
         │ （规格 JSON + 规则）   │     │ （永不进公开 Skill 仓）    │
         └────────────────────────┘     └────────────────────────────┘
```

## 4. 云端更新与迭代机制

### 4.1 单一事实源（SSOT）

| 资产 | SSOT | 消费者 |
|------|------|--------|
| GTLS 源码与 source-registry | `github.com/einkyhuang/global-trade-lead-search` @ `main` + semver tag | Desktop clone、Grok Bot workflows、Codex `~/.codex/skills` |
| DCA 源码 | **待建** `deep-client-analysis` 仓 | 同上 |
| 通用话术 JSON | `global-foreign-trade-skills-hub` | 各行业 Pack 通过 submodule / 发布包引用，**禁止再复制三份进 zhanfa 仓** |
| 展发面料等垂类 | `zhanfa-trade-skills-hub`（清洗后只留垂类） | foreign-trade-hub |
| 私有客户名录 | 私有数据仓或对象存储 + 只读 API（如 lightleads-api） | 查询类 Skill；**永不**进 public GTLS |

桌面 `超级外贸技能库` 定位为 **编辑与投递工作区**（待训练→已训练），不是第二套 SSOT。

### 4.2 版本与 CI

- 每个 Core/Pack：`VERSION` 或 SKILL frontmatter `version` + `CHANGELOG.md`（GTLS 已有）。  
- Tag：`gtls-v0.2.0`、`dca-v3.3.0`、`lighting-hub-v1.x`。  
- CI（GTLS 已有 `test.yml`）：`unittest` + `doctor.py`；DCA 可加「模板/配置器静态检查」与「无密钥扫描」。  
- 行业 Pack：校验 JSON schema（规格字段必填、禁止把客户邮箱写进 knowledge）。

### 4.3 同步到 Grok Bot 技能库与工作台

建议固定发布流水（人工或脚本，一步一确认）：

1. SSOT 仓 `main` 合并并通过 CI。  
2. 打 tag。  
3. 同步到：  
   - Box：`/home/box/agent-data/workflows/<skill>/`（Grok Bot Skill 库）；  
   - 工作台：相关 bot 的 `files/<skill>/`（如照明业务员）；  
   - 可选：Desktop `skills/` 仅作开发机镜像，`git pull --ff-only`。  
4. 在 `digital-workshop/bots/管理中枢/最强大脑/notes/` 留一条发布记录（版本、hash、影响 bot）。  
5. **私有客户数据**只走 API/私有盘；工作台 git（`einkyhuang/digital-workshop`）继续用 `.gitignore` 挡掉。

### 4.4 「持续训练」闭环（对齐现有 SOP，补执行）

1. 文件投入 `超级外贸技能库/01_.../待训练` 或 `02_<行业>/待训练`。  
2. 统一 ingest（修正脚本路径，纳入工作台或 `03_IDE` 包）。  
3. 规范化写入 JSON → PR 到对应 GitHub 仓。  
4. Deploy Cloudflare Worker / 刷新 Pack。  
5. 归档到「已训练」；企微/Bot **拉新版本**而非热改私有客户表。

## 5. 调用设计

### 5.1 Skill 名（给 Agent / Grok Bot）

| 用户说法 | 应加载 |
|----------|--------|
| 超级搜索、找进口商/经销商、公网线索 | `global-trade-lead-search` |
| 客户深度分析、背调、出 MD/HTML 报告 | `deep-client-analysis` |
| 照明询盘/规格/报价/开发信 | `lighting-trade-hub`（内部可再调 GTLS/DCA） |
| 服装面料询盘/匹配 | `foreign-trade-hub` |
| 查已有照明名录 | `client-query-skill` / lightleads API |
| 汽配广交会名录 | `auto-client-skill`（升级后 `auto-parts-trade-hub`） |

### 5.2 输入 / 输出契约（摘要）

**GTLS**  
- In：`query`, `country[]`, `customer_types[]`, `limit`, `exclusions`, `lang`, `freshness`  
- Out：leads 表（name/domain/geo/type/evidence/verification/confidence）+ coverage；缺证据标 `待验证` / `公开渠道未找到`  
- CLI：`python3 scripts/trade_lead_search.py --query ... --country ... --limit ... --out-dir ...`

**DCA**  
- In：目标市场、客户名/官网、模块集合、（可选）我方公司  
- Out：`reports/<slug>-analysis.md` + `.html`  
- UI：优先 `configurator.html`；无 GUI 时用文字补全清单（Skill 已规定）

**行业 Pack**  
- In：询盘字段 / 星级 / 邮件章节  
- Out：结论 + 证据边界 + 英文草稿 + 待填变量；**默认不发送**

### 5.3 CLI / API / MCP

| 通道 | 适用 | 现状 / 建议 |
|------|------|-------------|
| Agent Skill（SKILL.md） | Grok Bot、Codex、Cursor | 主力；保持 frontmatter `name` 稳定 |
| CLI | 批跑、CI、文件夹协作 inbox | GTLS 已具备；DCA 可补 `scripts/run_analysis.py`（配置 JSON → 双文件） |
| HTTP API | 跨机器、企微、小程序 | 通用中台：Cloudflare Worker；照明名录：Vercel `lightleads-api`；本地：`127.0.0.1:8989` |
| MCP | 浏览器辅助发现 | `全能搜索skills/config/mcporter.json` 已有浏览器 agent 示例；GTLS 主流程仍应走官方 search/Firecrawl 适配器，MCP 作补充 |
| 文件夹 inbox | Codex / agy 协作 | 可把「跑一批 GTLS」写成 `AI协作中间层/inbox` 任务，结果回 `outbox`（与现有协作方案兼容） |
