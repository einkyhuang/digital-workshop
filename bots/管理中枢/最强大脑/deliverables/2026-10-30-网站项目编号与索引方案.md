### 1.4 核心问题（为何要编号）

1. **命名不统一**：英文品牌、中文公司名、功能描述混用（`网站-重庆云昇` vs `MGOO` vs `照明网站`）。  
2. **一客户多路径**：Gongly 桌面副本 + 归档夹；Gangsha 符号链接漂在「桌面未整理」；AK 在桌面与「已交付」各一份。  
3. **巨型混合目录**：MGOO/Gongly 把代码、PDF 画册、广告素材、旧试版堆在同一层，派「更新产品」时不好定位 `03-产品`。  
4. **无机器可读索引**：bot / Codex / agy 无法靠「001」解析路径与默认执行器。  
5. **平台资产与客户站混放**：主题 zip、WordPress 插件、报价模板占桌面，干扰客户项目检索。

## 2. 命名规范：`NNN-品牌名`

### 2.1 规则

- **格式**：`NNN-品牌英文或通用简称`（三位数字，品牌用 ASCII，便于终端与 git）。  
- **口语**：可说「001」「001 MGOO」「001 的网站」——索引里用 **别名** 覆盖中文公司名。  
- **文件夹最终形态**（整理后）：`网站项目/001-MGOO/`，内部标准子目录见 §3。  
- **号段**：
  - `001–099`：客户建站项目（含已交付归档）  
  - `800–899`：自有产品 / 平台站（Forwelike、TradeCraft、标准后台等）  
  - `900–949`：仅合同 / 空壳 / 暂停占位  
  - `950–999`：设计案例库、主题插件库等非客户交付物（可选，也可不编号只放 `网站资产/`）

## 3. 快速索引设计

### 3.1 文件位置（整理后权威位置）

建议放在：

`~/Desktop/网站项目/项目索引.md`


### 3.4 单项目标准目录模板

```
NNN-品牌名/
  README.md          # 编号、域名、仓库、怎么本地跑、最近交付
  00-资料/           # 合同扫描件、品牌手册、会议纪要（无密钥）
  01-设计/           # Figma 导出、LOGO、画眉产出
  02-代码/           # 唯一权威 git 工作副本（可再分子站）
  03-产品/           # 产品图、CSV、画册 PDF、待上架清单
  04-交付/           # 给客户的 zip、验收截图、上线记录
```

旧的「试版 / _副本 / dist / node_modules」不进模板主层；大文件可留在 `03-产品` 或外置硬盘，索引里只记相对路径。

### 3.5 一句话如何映射（核心体验）

**用户说**：`001 MGOO 更新产品`

**解析步骤**（大可可 / 码码 / Codex 共用）：

1. 从 `projects.json` 取 `id=001` → `path`、`owner_bot=码码`、`default_runner=codex`、`common_tasks` 含「更新产品」。  
2. 工作目录：`{path}/03-产品`（资料）+ `{path}/02-代码`（改站）。  
3. 派活：给码码；码码在 Mac 上对 `02-代码` 执行  
   `codex exec "...根据 03-产品 的新资料更新站点产品页..."`  
   （或 `agy -p "..."`，若该条 `default_runner=agy`）。  
4. 完成后结果写入 `{path}/04-交付/` 与 AI 协作中间层 `outbox/`，再请你确认上线。

**分工默认**：

| 任务类型 | Bot | 默认执行器 |
|----------|-----|------------|
| 改代码 / 部署 / 主题 | 码码-前端程序员 | Codex（GPT-6.1 Sol） |
| 视觉 / 版式 / 物料图 | 画眉-设计师 | agy（Gemini 3.8 Flash） |
