> 作者：搜搜-SEO专家（`bots/网站项目/Super-SEO-Hub/`）

> 数据源：智能日程管理（SmartPlan Hub）`website_projects` 表（当前 workspace 同步 **53** 条）  
> 依据源码：`智能日程管理/server/db.js`、`websiteService.js`、`超级工作台应用/scripts/sync-smartplan.mjs`、`Models.swift` / `ProjectsView.swift`  
> 版本：v1.0 · 2026-10-29（Asia/Shanghai）

## 0. 范围与原则

1. **单一事实来源**：以 SmartPlan Hub SQLite 表 `website_projects` 为准；工作台经 `sync-smartplan` 双向同步到 `workspace.json → websiteProjects[]`。
2. **不同步、不展示账号密码类字段**（见 §0.1）。
3. **状态双字段**：`status`（英文机读）与 `category`（中文展示）必须成对维护，禁止只改其一。
4. **SEO 检查项**按 SeoHub 双轨（传统 SEO + GEO）定义，挂在每个项目上，可独立打勾与记分。

### 0.1 明确排除的既有字段（禁止进列表 / 详情 / 写回）

| 源表字段 | 说明 | 处理 |
|---|---|---|
| `assets_credentials` | 域名账号、服务器登录、CMS 登录等凭证 JSON/文本 | **永不展示、不同步、不进表单** |
| `client_phone` | 客户手机 | 仅存 SmartPlan；工作台不同步、不展示 |
| `client_wechat` | 客户微信 | 同上 |
| `client_email` | 客户邮箱 | 同上 |

> 与 `sync-smartplan.mjs` 现有注释一致：`intentionally omit phone/wechat/email/credentials`。  
> 如需联系客户，跳转 SmartPlan Hub CRM，不在工作台缓存明文。

## 1. 列表列定义（顺序固定）

列表为表格视图时，按下列 **从左到右** 顺序渲染。卡片紧凑视图可只显示加粗列。

| # | 列标题 | 字段（源表 / 工作台 camelCase） | 展示规则 | 可排序 | 可筛选 |
|---|---|---|---|---|---|
| 1 | **项目名称** | `name` | 加粗；空值禁止 | ✓ | 搜索 |
| 2 | **状态** | `category`（辅：`status`） | 色标 Chip：进行中蓝 / 已交付绿 / 功能基础建设紫 / 已暂停·挂了橙 | ✓ | ✓ Chip |
| 3 | **客户** | `client_name` + `client_company` → `clientName` / `clientCompany` | `姓名 · 公司`；皆空显示 `—` | ✓ | 搜索 |
| 4 | **网址** | `url` | 可点击外链；空显示 `—`；截断显示域名 | ✓ | 搜索 |
| 5 | **框架** | `framework` | 文本 Chip，默认 `React` | ✓ | ✓ |
| 6 | **服务** | `services`（JSON 数组） | 多 Chip：`网站搭建` / `SEO/GEO` / `科学上网` 等 | | ✓ 含 SEO |
| 7 | **进度** | `progress`（工作台字段，**新增建议持久化**） | 进度条 + `N%`；默认按状态映射（见 §3.3） | ✓ | |
| 8 | **付款** | `payment_status` → `paymentStatus` | `pending`→待付款 / `deposit_paid`→已付定金 / `fully_paid`→已结清 | ✓ | ✓ |
| 9 | **服务截止** | `deadline` 优先，否则 `service_end_date` | `YYYY-MM-DD`；过期标红 | ✓ | |
| 10 | **负责人** | `ownerBotId`（工作台字段） | 员工名；空=`未指定` | ✓ | ✓ |
| 11 | **最近更新** | `updated_at` → `updatedAt` | 相对时间 + 悬停绝对时间 | ✓ **默认** | |

### 1.1 默认排序

1. **主排序**：`updated_at DESC`（与 SmartPlan / sync 脚本一致）  
2. **次排序**：同更新时间下按 `status` 优先级：`in_progress` → `infrastructure` → `delivered` → `inactive`  
3. **分组筛选默认**：`全部`；常用快捷：`进行中`、`含 SEO/GEO 服务`

### 1.2 列表不展示但行内可点进详情的字段

`id`、`description`、`local_path`、金额明细、SEO 检查项摘要（详情内展示）。

## 3. 状态流转规则

### 3.1 状态枚举（成对）

| `status`（机读） | `category`（中文） | 默认 `progress` | 色标 |
|---|---|---|---|
| `infrastructure` | 功能基础建设 | 25 | 紫 |
| `in_progress` | 进行中 | 55 | 蓝 |
| `delivered` | 已交付 | 100 | 绿 |
| `inactive` | 已暂停/挂了（兼容旧值「挂了」） | 0 | 橙 |

当前 53 条分布参考：已交付 44 · 进行中 5 · 功能基础建设 2 · 已暂停/挂了 2。

### 3.2 允许的转换

```
                    ┌──────────────────┐
                    │  infrastructure  │
                    └────────┬─────────┘
                             │ 需求确认 / 开工
                             ▼
┌──────────┐  暂停/客户失联   ┌─────────────┐   验收通过   ┌───────────┐
│ inactive │◄────────────────┤ in_progress │─────────────►│ delivered │
└────┬─────┘  恢复跟进       └──────▲──────┘              └─────┬─────┘
     │                              │                           │
     └──────────────────────────────┘                           │
              重新激活（需备注原因）          返修/续约 SEO ◄──────┘
```

| 从 → 到 | 是否允许 | 进入条件 | 退出/附加动作 |
|---|---|---|---|
| → `infrastructure` | 新建默认可选；从任意状态可退回 | 有 `name` + `local_path` 或明确「仅策划」 | 进度≤25；清空「已交付」里程碑勾选可选 |
| `infrastructure` → `in_progress` | ✅ | 具备可访问 `url` **或** 本地可预览路径；至少一项 `services` | 进度默认 55；创建 SEO 检查清单骨架 |
| `in_progress` → `delivered` | ✅ | **若服务含 SEO/GEO**：全部 **P0** 检查项必须 `pass`；付款建议非 `pending`（可强提醒、可管理员覆盖） | 进度=100；写 `seo_last_audit_at`（若有体检） |
| `delivered` → `in_progress` | ✅ | 填写返修/续约原因（跟进 note） | 进度调回 70（可改） |
| `*` → `inactive` | ✅ | 必填挂起原因（跟进 type=`note`） | 进度=0；保留 SEO 分数只读 |
| `inactive` → `in_progress` / `infrastructure` | ✅ | 必填重启说明 | 恢复原进度或按目标状态默认值 |
| `delivered` → `inactive` | ✅ 慎用 | 站点下线/域名放弃 | 记录原因 |
| `infrastructure` → `delivered` | ❌ 禁止跳过 | — | 须经 `in_progress` |
| `inactive` → `delivered` | ❌ | — | 须先回到进行中并验收 |

### 3.3 进度默认映射（与现 `ProjectsView.defaultProgress` 对齐）

| status | progress |
|---|---|
| `delivered` | 100 |
| `in_progress` | 55 |
| `infrastructure` | 25 |
| `inactive` | 0 |

手动改进度不自动改状态；改状态时**仅当**用户未锁定进度时套用默认值（实现可：状态按钮覆盖；编辑器 Stepper 手改优先）。

### 3.4 付款状态（独立，不替代项目状态）

`pending` → `deposit_paid` → `fully_paid`  
允许回退（如退款）但必须写跟进。与项目 `status` 无硬绑定；仅在「进行中→已交付」时做软校验。

## 4. 每项目 SEO 检查项（SeoHub 双轨）

适用：`services` 含 `SEO/GEO` 或负责人勾选「纳入 SEO 巡检」的项目。  
每项：`id` · 名称 · 轨道 · 优先级 · 通过标准 · 证据。

### 4.1 检查项总表

| ID | 检查项 | 轨道 | 优先级 | 通过标准（Pass） |
|---|---|---|---|---|
| `robots_txt` | robots.txt 可访问且非软 404 | SEO+GEO | **P0** | `GET /robots.txt` → 200，`Content-Type` 文本；正文含 `User-agent`；**不是**首页 HTML |
| `ai_crawler_allow` | AI 搜索爬虫放行 | GEO | **P0** | robots 显式/默认允许：`OAI-SearchBot`、`PerplexityBot`、`ClaudeBot`、`Bingbot`；无全站 `Disallow: /` 误伤；无不当 `noindex` |
| `sitemap_xml` | sitemap.xml 有效 | SEO+GEO | **P0** | `GET /sitemap.xml`（或 robots 声明的 URL）→ 200；含 `<urlset>`/`<sitemapindex>`；robots 中有 `Sitemap:` |
| `ssr_readable` | 首包机器可读正文 | GEO | **P0** | 禁用 JS 抓取：可见正文 ≥ 页面文本目标的约 85%；非近空白 SPA 壳 |
| `title_h1_meta` | Title / 唯一 H1 / Meta Description 在首包 | SEO+GEO | **P0** | 首包 HTML 含 `<title>`（约 35–60 字）、恰好 1 个 `<h1>`、meta description（约 120–160 字） |
| `canonical` | 自引用 Canonical | SEO+GEO | **P0** | `<link rel="canonical" href="...">` 指向规范 HTTPS URL，无错误交叉 |
| `https_status` | HTTPS 与主文档状态码 | SEO | **P0** | 主 URL 200（或正确单跳转至 HTTPS 200）；证书有效 |
| `json_ld` | JSON-LD 结构化数据 | GEO | **P1** | 至少 `Organization` 或 `WebSite`；推荐 `@graph` + 页面类型（Article/FAQ/Product 等） |
| `same_as` | 实体 sameAs | GEO | **P1** | Organization.`sameAs` 含 ≥1 权威外链（社交/百科/企业库） |
| `og_twitter` | Open Graph / Twitter Card | SEO+GEO | **P1** | `og:title`、`og:description`、`og:image`、`og:url` 在**首包**（非仅客户端注入） |
| `lang` | html lang 与内容语言一致 | SEO+GEO | **P1** | `<html lang="...">` 与主语言一致（中文站勿误标 `en`） |
| `llms_txt` | llms.txt（及可选 llms-full.txt） | GEO | **P1** | `/llms.txt` 200；含品牌一句话定义与核心 URL 列表 |
| `cwv` | Core Web Vitals | SEO | **P1** | 实验室或 CrUX：LCP&lt;2.5s、INP&lt;200ms、CLS&lt;0.1；超标记失败并附指标 |
| `heading_hierarchy` | 标题层级与 BLUF | GEO | **P2** | H1→H2→H3 不跨级；核心节首句结论先行 |
| `alt_internal_links` | 图片 Alt 与内链 | SEO | **P2** | 主内容图 Alt 覆盖；主导航/正文有合理内链 |
| `gsc_submitted` | GSC 属性与 Sitemap 提交 | SEO | **P2** | 已验证 Search Console 属性；Sitemap 提交成功（人工确认勾选） |
| `index_coverage` | 索引/发现健康 | SEO | **P2** | 无大面积软 404；关键页可被抓取（抽检） |
| `backlinks_baseline` | 外链基线 | SEO | **P2** | 记录引用域名数与风险集中度；单一来源占比过高则标 ⚠️ 非必 Fail |

### 4.2 优先级与门禁

- **P0**：含 SEO/GEO 服务的项目，**进入 `delivered` 前必须全部 Pass**（管理员可写明原因覆盖，记入跟进）。  
- **P1**：交付后 14 日内清零；未清零项目在列表显示黄点。  
- **P2**：迭代优化；纳入月度巡检。

### 4.3 推荐存储结构（🆕 `seo_checklist`）

```json
{
  "robots_txt": { "pass": true, "priority": "P0", "note": "200 OK", "updatedAt": "2026-10-29T03:00:00+08:00" },
  "ssr_readable": { "pass": false, "priority": "P0", "note": "首包无正文，CRA 壳", "updatedAt": "2026-10-29T03:00:00+08:00" }
}
```

体检产物命名建议：`{domain}-seo-geo-audit-report.md` / `.html`，存本 bot `deliverables/` 或客户项目 `files/`，路径回写 `seo_report_*`。

### 4.4 与自动化脚本对齐

执行 SeoHub：`python3 scripts/audit.py <url> --output-dir <dir>`，将报告分与失败项同步进 `seo_score` / `geo_score` / `seo_checklist`。

## 6. 管理流程（工作台操作要点）

1. **导入**：顶部「同步」← SmartPlan（53 条）；只读敏感字段已被脚本剥离。  
2. **列表**：默认按最近更新；Chip 筛分类；搜索命中名称/客户/URL/状态。  
3. **详情**：六区展示；「快捷改状态」走 §3 校验（含 SEO P0 门禁）。  
4. **编辑**：表单不含电话/微信/邮箱/凭证；保存置 `dirty=true`。  
5. **写回**：同步 `--push`：已有 id 走 API PUT；本地新建可走 SQLite INSERT；仍不写回敏感字段。  
6. **SEO 巡检**：负责人（搜搜）对开通 SEO 的项目跑 audit → 更新分数与 checklist → 报告进 deliverables。
